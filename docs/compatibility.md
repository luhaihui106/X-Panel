# 兼容性分层与未完成门禁

## 如何解释验证

| 层级 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 源码与回归 | 指定提交的构建、Go/Node 回归和隔离 API/UI 检查 | 全部平台、生产环境或任意未来上游版本兼容 |
| 二进制/容器运行 | 指定架构、系统镜像、运行方式下程序可执行，SQLite/接口与测试操作通过 | 原生宿主启动、重启、内核差异或真实宿主升级 |
| 安装与服务操作 | 指定安装包及服务管理器的实际检查范围 | 容器检查等于完整 systemd/OpenRC 宿主开机验收 |
| 授权实际部署 | 某个环境、精确包、核对与回退流程 | 所有发行版或用户可以无备份直接安装 |

本地候选交付有 Linux ARM64/AMD64 静态 CGO SQLite 包与来源/校验记录，但尚未发布到本仓库 Releases。ARM64 原生与 AMD64 QEMU 的运行证据需区分；模拟器不是原生 AMD64 宿主验收。已有平台证据可复用，但不能把之前核心/后台验证全部写成当前首页改动重新完整测试。Rocky Linux 10 属于已排除范围，不列为待通过目标。文档整理本身不重新打包、不执行安装或部署。

## 明确保留的限制

- destructive read → SQLite commit 之间崩溃可丢失内存 pending 流量，没有跨系统 durable acknowledgement。
- 真正未知非零流量身份 fail closed，保留整批增量并阻塞进一步采集/月重置，需诊断所有权后处理。
- 退休身份归档保留统计及身份预留；未验证核心代际屏障前不允许安全复用，也无自动 GC。需考虑归档增长和隐私/备份。
- 数据库提交后的核心增删失败转为异步重启/协调请求；重启也可能失败，不保证即时 DB/core 一致性。
- 旧 `go vet` 问题见[月重置报告](downstream-monthly-reset.md)；`-vet=off` 测试通过不能声称 vet 全绿。
- 当前 HEAD 删除凭据不清除已公开历史，不证明泄露凭据已撤销；本次不改写历史。

## 正式发布前门禁

上游同步、功能与文档 PR 已授权合并 main；正式发行仍需单独授权。继承 release/Docker 工作流已改为仅手动触发，源码合并不自动构建发行包或部署。独立审查结论、最终接收的提交与包身份、目标宿主安装/重启/升级/回滚范围、备份与迁移方案、再分发资产许可以及发布/下载路径需明确批准。继承工作流和脚本仍含上游发布命名空间/下载地址，应另行审计和修订后再建立派生发行入口。不能因本文档通过或某个受控部署成功而自动 merge、tag、release 或普遍承诺生产就绪。
