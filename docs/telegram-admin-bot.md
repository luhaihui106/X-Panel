# Telegram 管理员机器人

本说明按免费源码的实际处理器编写；不是生产配置或在线通知验收。需要在面板开启 Telegram，配置自己的 bot token 和管理员聊天 ID；管理员权限按发送者 Telegram ID 校验。群聊接收 ID 不等于管理员用户 ID。本文不公开任何凭据。

## 保留的操作

- `/start`、`/help`：显示菜单；`/status` 是机器人响应状态，不是完整服务器监控；`/id` 返回自己的 Telegram ID。
- 管理员菜单：服务器用量、排序流量报告、在线客户端、入站与客户端查询、添加/编辑/删除客户端、额度与到期设置、启停、手动重置流量、数据库备份、封禁日志。具体协议支持仍以原处理器为准。
- `/usage <email>`：管理员查客户端；非管理员只能查询与自己 Telegram ID 绑定的客户端。`/inbound <remark>` 为管理员查询入站。
- `/restart`：管理员重启 Xray；`/restartx` 或菜单重启面板需要确认。**这些操作会改变运行状态并可能短暂断网**；原回复不等于独立健康检查。
- `/subconverter`：检测订阅转换服务；不存在时可确认安装，保留原安装及结果通知。**安装会改变服务器**，本次源码清理没有执行安装或修改安装器。

已移除抽奖入口/回调/开奖/邀请、每日诗词、随机美图、新闻抓取、VPS 推荐/affiliate，以及 Telegram 一键配置的 Pro 购买占位命令和按钮；不解锁任何 Pro 功能。旧抽奖数据库表和历史数据继续兼容，不执行删除表或数据迁移。

## 一般会通知什么

| 通知 | 条件与边界 |
| --- | --- |
| 管理员运营摘要 | 开启 bot 后按 `tgRunTime` 的 cron 执行；为空回退 `@daily`，按面板时区。现有任务要求 Xray 正在运行。每名管理员一条，包含实际服务器运行时长、CPU、内存、磁盘、TCP/UDP、主机累计网络流量、面板/Xray 版本及核心状态；不抓诗图新闻，也不为报告查询公网 IP。主机网络流量不是客户端周期用量。 |
| CPU 超阈值告警 | `tgCpu > 0` 才注册检查；10 秒采样，连续三次超阈值才通知，两次至少间隔 10 分钟。保留原行为。 |
| 登录成功/失败 | bot 运行且 `tgBotLoginNotify` 开启；保留原行为。**继承的失败登录通知会包含尝试的密码，是既有敏感信息风险；本次不扩展范围修改它。**建议仅发送到受控私人管理员聊天，不要转发通知或公开载荷。 |
| 设备超限提醒 | 入站启用且设置设备限制，核心运行、可读取访问日志并识别客户端；持续超限约三分钟触发原设备限制处理时发送管理员通知。通知不是独立证明核心封禁成功；没有新增解封通知。 |
| 数据库备份 | 管理员菜单或已认证的 `/panel/api/backuptotgbot` 请求触发；没有自动定时备份任务。数据库含敏感配置，只交给受控管理员。 |
| 订阅转换结果 | 用户确认安装后，原安装流程发送完成/失败等结果及已有相关警告；不代表无人操作就会安装。 |
| 重启操作回复 | 管理员手动发起/确认时返回原确认、取消或结果提示；没有新增启动/掉线监控。 |

额度将尽/即将到期及禁用情况仍可从管理员菜单查询。源码保留客户端 Telegram ID 的额度/到期提醒辅助函数，但当前没有发现调用或定时注册，**不宣称会自动发送**。独立月重置没有 Telegram 专用开关或自动完成通知，本次不新增。

## 验证与部署边界

回归测试通过本地 Telegram API 接收真实菜单与报告载荷，验证已退役回调无动作、正常管理员菜单保留、摘要为单条且无额外 HTTP 获取。测试使用临时数据库和合成 bot 标识，不调用生产 bot、重启或安装。源码合并不等于已部署：已安装面板须另获授权重建/替换程序才会生效。
